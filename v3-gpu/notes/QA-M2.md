## Defects

**D1 — Medium. Canvas backing height ≠ displayed box when the CSS height is fractional → 1 device px vertical drift + compositor resample.** `src/main.ts:103-110`. Centrifuge canvas box is 652 × 774.25 CSS px. Under CDP device-scale emulation (capture.mjs, drive.mjs, gate tooling) `devicePixelContentBoxSize` reports the *snapped box in CSS px* (652 × 774), so the "agrees" check fails and the backing becomes `round(774.25·2) = 1549` rows while Chrome displays the canvas in 774·2 = 1548 rows. Measured: GPU content 0 px off at the top, ~0.6 px mid, ~1.0 device px too high at the bottom (DPR 2, 3, 4; `shift.mjs`), and downsampled GPU@DPR4 vs GPU@DPR1 shows the same drift (SVG is self-consistent) → it is the GPU path. Effect: the whole DPR≥2 gate residual (0.26–0.32 % → 0.008 % when fixed), 391 px @DPR3 0.488 % → 0.011 %, and very likely FINDINGS-M2 "452 px mobile-emulated 0.62 %" gap (re-measured 0.42 %). Fixture never shows it because 408 CSS px is integral. Repro: `node gates.mjs` vs `node snapgate.mjs`. Fix: when the device box does not agree, use `dev.inlineSize·dpr × dev.blockSize·dpr` (snapped) rather than `round(css·dpr)`; FINDINGS-M2 tooling note 1 should say "reports the snapped box in CSS px" rather than "CSS px". Real-display behaviour not verified (no emulation there), but the gates and every DPR≥2 crop in `out/gpu/crops/` are affected.

**D2 — Medium (needs real-hardware confirmation). Fractional DPR (browser zoom 125 % / 175 %) renders softer than SVG.** DPR 1.25: 0.69 % / strict 1.13 %; 1.75: 0.54 % / 0.97 %; 1.5: 0.05 % (fine). Not fixed by D1's workaround (0.71 / 0.52 %). GPU tach ticks, rims and every vertical line are visibly blurred — compositor resampling of the canvas at a non-integral device position/scale. Crop: `crops/bz125.png`. 125 % is a common Windows default.

**D3 — Low. Ancestor CSS `zoom` does not scale hairlines.** SVG non-scaling strokes are 0.6 *zoomed* CSS px (0.9 visual px at zoom 1.5); GPU keeps `dpr = width / cssW` from the visual box (`src/main.ts:108`) → GPU lines ~33 % lighter. Also the ResizeObserver does not fire on a zoom change (device box unchanged). Zoom 1.5 @DPR2: 0.745 % / strict 1.91 %; 0.8: 0.41 %; applied before load: 0.61 % @DPR1. Crops: `crops/cz15.png`, `crops/pz-1.png`, `crops/pz-2.png`.

**D4 — Low (latent). Translucent gradient stops render opaque.** `src/renderer.ts:169,250` classify a paint as opaque from the paint alpha only (gradient paints carry alpha 1); `src/shaders.ts:146` (`fillFragOpaque`) then forces alpha 1, so a `stop-opacity:.4` stop draws solid. Crop: `crops/blend-light-dpr1.png` (right-hand disk: SVG light grey, GPU dark grey). Centrifuge funnel stops are opaque today, so no visible effect on the gate.

**D5 — Low (latent). The canvas clips at the viewBox; the kit SVG overflows visibly.** Same crop (`crops/blend-light-dpr1.png`: base slab cut at the bottom/right in GPU). M1 asserts every vertex is inside the viewBox, but stroke halves, the 9 px halo blur and future live content near the edge can still extend outside.

**D6 — Low. GPU resource leaks.** `src/renderer.ts:357` destroys halo textures `a`/`b` on resize but not the `blurH`/`blurV`/`params` uniform buffers (3 buffers + 3 bind groups per resize; a resize storm leaks them). `src/renderer.ts:340` drops `haloTex` without destroying anything when the palette classification changes.

**D7 — Low / perf. Blank canvas during boot; GPU cost.** First submit ≈ 80 ms after navigation (warm adapter; cold adapter +140 ms), but `__gpu.ready` ≈ 305 ms: `onSubmittedWorkDone` waits ≈ 225 ms for lazy pipeline compilation; first-frame CPU encode 6–8 ms (FINDINGS says ≈ 9). The SVG `<template>` is only shown on failure (`src/main.ts:41-46`), so the figure is empty for ~0.3 s on load (M4 should show the SVG until the first present). Steady state with `--enable-webgpu-developer-features` timestamps: encode p50 0.2 ms, p95 0.3–0.4 ms; **GPU pass p50 2.9–5.2 ms, p95 7–8 ms, max 9.5 ms** for the static centrifuge (DPR 1/2/3; Apple GPU at idle clocks, so noisy) vs 0.5 ms for the fixture — 21 050 segment instances, each fragment running the ±3 neighbour ownership loop (`src/shaders.ts:229-242`). Worth profiling before M3 adds per-frame work.

**D8 — Info. `setTheme` probes the palette twice** (`src/main.ts:137` calls `probe()`, then the MutationObserver at `:132` fires): 676 `getComputedStyle` calls instead of 338 (~1.5 ms; harmless).

**D9 — Parity notes on hairline weight at DPR 1 (quality bar).** GPU follows exact area coverage; Chrome's SVG raster is heavier on some paths depending on path *structure*, not geometry: the `centrifuge.rail#2` bottom edge (one 2:1 segment) renders 48/48 per column as a single-segment path but 63/63 once the same path has one more segment or subpath (`exp2.mjs`). Visible consequences at 1×: rail#2 edge −36 % column ink (`crops/halo-centrifuge-dark-dpr1.png`, diagonal red line), the abutting `centrifuge.leg#3` / `stub.belt.leg#6` silhouette edges 35 % lighter at DPR1 and a light seam pixel at DPR4 (169 vs 138) (`crops/leg-centrifuge-light-dpr1.png`, `…-dpr4.png`), the vertical tach tick −20 % (`crops/tach-centrifuge-light-dpr1-z8.png`), lamp lens ring −6 % (`crops/lamp-centrifuge-dark-dpr1-z10.png`). Isolated lines: the QA sheet (`make-iso.mjs`, 20-phase sweeps) puts 2:1 and vertical lines at 0.85–1.07 across all phases and DPRs, and abutting pairs at 0.94–1.10 → GPU is correct; the reference is inconsistent. 45° hairlines @DPR1 vary 0.63–1.31 per phase at 0.4 px and 0.84–1.12 at 0.6 px (calib sheet: 45° 0.4 px = 0.65, 0.6 px = 1.13). Short 0.4 px ticks +47 % (documented). Everything else at 1× matches: eye, crank, belt and feed stubs (0 px diff), grease nipple, strobe, tach, oiler, funnel void gradient, bolt dots, halo edge (0 px), four-tone faces, seamless 0.4 px tones; edges end on strokes, no seams or fringes (crops `crops/{eye,nipple,crank,tach-lamp,beltstub,strobe,oiler,feedstub,halo}-centrifuge-{light,dark}-dpr{1,4}.png`, `crops/funnel-centrifuge-dark-dpr1-z5.png`, `crops/flange-dots-centrifuge-dark-dpr1-z6.png`, `crops/cabinet-centrifuge-light-dpr2-z5.png` = AA-only differences).

**D10 — Info. Depth precision claim.** Centrifuge: 240 items, 1 783 prims, 1 789 depth slots, all distinct in f32. `1 − (seq+1)/(total+2)` stays strictly monotone up to ≥ 8 M slots and breaks between 8 M and 16 M (1.1 M collisions at 16 M) — the "exact integers < 2^24" wording in PLAN-M2 overstates it by 2×; irrelevant at this scale.

**D11 — Info. `tools/lockstep.js:25` — `step(k)` never resolves when no rAF callback is pending** (the renderer only requests frames on change), so `await __lockstep.step(1)` hangs on an idle page.

## Test-value review (low-value-test-dictionary)

- **No committed M2 gate.** The gates were driven by `out/tmp/*.json` (gitignored: rt.json, sweep.json, gpu1.json); no thresholds are asserted and PLAN/FINDINGS record no numbers → not reproducible, and D1 went unnoticed. Category 10 (no assertion). Recommend `tools/gate-m2.mjs` mirroring M1's `gate.mjs` (asserted thresholds + a `--mutate` self-test), including a non-integral-height page.
- **Fixture (`src/fixture/make-fixture.mjs`) — keep, but it does not cover what PLAN says.** `blendedVertices: 0`: the "translucent group" and ".55 packet lines" are strokes, so `fillFragOver` / `fillFragMultiply` / `fillFragScreen` and gradient alpha (D4) are exercised by nothing in M2. The 408 px (integral) height hides D1. Add a blend item (QA `make-blend.mjs` is a template) and a fractional-height variant.
- **Calibration (`make-calib.mjs` + `measure-calib.mjs`) — keep, fix.** Means per kind×width hide per-angle and per-phase failures (45°/0.4 px = 0.65 averages into 0.96); it lacks the dominant 2:1 iso slope, phase sweeps, abutting lines and lines on fill boundaries; it prints ratios without pass/fail (category 10); origin `[30, 58]` and `svgCssWidth` duplicate kit layout and the 6 px capture margin (category 8, brittle).
- **`src/fixture/svg2scene.mjs` — duplicate coverage (category 6).** It re-implements the M1 exporter's parsing (`export/svgsub.mjs`) and tessellation (`export/tess.mjs`), so the fixture follows a different path from the real DL. Generate the fixture DL through `export/` and delete it.
- **`tools/build.mjs:57-58`** lists `fixture-share1` variants and then filters them out → dead entries (category 9).
- **`tools/diff.mjs:20-26`** silently crops mismatched sizes to the top-left common area, which can hide off-by-one size bugs such as D1. Make it a warning that fails under `--strict`.
- **Committed artifacts:** `out/gpu/crops/dev/*` are debug crops with no consumer (orphaned); the DPR2/DPR4 crops carry D1's drift.
- Orphaned-tooling sweep: `lockstep.js` has no committed consumer yet (planned for M3, so keep). `subpathsOf` is exported but used only inside svg2scene.

## Out-of-scope findings (v2 / kit / tooling)
- Chrome's SVG hairline weight depends on path structure (D9 repro `exp2.mjs`). v2 itself has inconsistent edge weights at DPR1 (rail and leg edges heavier than equivalent single-segment lines).
- Kit pages bake the theme into `body[data-theme]` and do not follow `prefers-color-scheme`; the GPU's OS-scheme listener is correct but only matters for pages that opt in.
- The lamp `.cf-glow` multiply/screen rule exists only for live slots; the static frame cannot verify it (QA sheet does).
- `tools/gate.mjs:100` strips module scripts greedily (`[\s\S]*`) and `tools/build.mjs:47` non-greedily. Both work today only because the second `<script type="module">` in the v2 page is inside a JS string — fragile.
- CDP tabs that are not in front pause rAF: any multi-tab drive/capture tooling must `Page.bringToFront` before waiting on frames (this hung QA's first run).
